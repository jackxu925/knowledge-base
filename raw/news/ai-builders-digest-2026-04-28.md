### Anthropic Engineering: Claude Code Auto Mode — A Safer Way to Skip Permissions

Anthropic introduced **Auto Mode** for Claude Code — a middle ground between manual approval (93% accepted anyway, causing approval fatigue) and `--dangerously-skip-permissions` (zero guardrails). The system uses a **two-stage transcript classifier** running on Sonnet 4.6:

- **Stage 1**: Fast single-token filter tuned to block aggressively (8.5% FPR, 6.6% FNR on real overeager actions)
- **Stage 2**: Chain-of-thought reasoning only for flagged actions (drops FPR to 0.4%, FNR rises to 17%)

The architecture has two defense layers: an input-layer **prompt-injection probe** that screens tool outputs before they reach the agent, and an output-layer transcript classifier that evaluates each action. Critically, the classifier is **reasoning-blind by design** — it only sees user messages and tool calls, stripped of assistant text and tool results to prevent the agent from talking the classifier into bad decisions.

Key threat model covers four scenarios: overeager behavior (taking initiative beyond authorization), honest mistakes (wrong blast radius), prompt injection (external instructions hijacking agent), and misaligned models. Real-world evaluation on 10,000 internal traffic actions shows the full pipeline achieves 0.4% FPR with 17% FNR on overeager actions — a substantial improvement over unguarded autonomous operation.

> "The classifier doesn't need to be flawless to be valuable. The starting point is catching enough dangerous actions to make autonomous operation substantially safer than no guardrails."

https://www.anthropic.com/engineering/claude-code-auto-mode

### Anthropic Engineering: Claude Code Auto Mode — 更安全的权限跳过方式

Anthropic 为 Claude Code 推出了 **Auto Mode**——介于手动审批（93% 被批准，导致审批疲劳）和 `--dangerously-skip-permissions`（零防护）之间的中间方案。系统使用运行在 Sonnet 4.6 上的**两级转录分类器**：

- **第一级**：快速单 token 过滤器，偏向阻止（FPR 8.5%，真实过度行为 FNR 6.6%）
- **第二级**：仅对被标记的操作进行链式思维推理（FPR 降至 0.4%，FNR 升至 17%）

架构包含两层防御：输入层的**提示注入探测器**筛选工具输出，以及输出层的转录分类器评估每个操作。关键设计：分类器**刻意不推理**——只看到用户消息和工具调用，剥离助手文本和工具输出，防止 Agent 说服分类器做出错误判断。

在 10000 个内部真实操作上的评估显示：完整流水线实现 0.4% FPR，过度行为 FNR 17%——相比无保护的自主运行是实质性改进。

### AI & I by Every — "The AI Model Built for What LLMs Can't Do"

**Guest**: Eve, Founder & CEO of Logical Intelligence

**The Takeaway**: Energy-based models (EBMs) represent a fundamentally different AI paradigm from LLMs — one that is token-free, self-verifying, and uniquely suited for mission-critical systems where correctness is non-negotiable.

Eve's company, Logical Intelligence, is building **EBMs with latent variables** (codenamed "Kona") focused on software and hardware correctness. Her core argument: LLMs are essentially playing a "guessing game" with tokens — autoregressive models that choose one direction at a time, can't turn back when they make mistakes, and lack internal verifiability. In her analogy, an LLM navigating San Francisco is like someone with tunnel vision who can only walk forward, sometimes falling into holes they can see but can't avoid because they're constrained by token-by-token generation.

EBMs, by contrast, operate like having a **bird's-eye view of an energy landscape** — they can see all possible states simultaneously, choose different routes when obstacles appear, and are **non-autoregressive** (no token sequences). This comes from physics: just as physical systems minimize energy to find stable states (like a tired person ending up on a couch), EBMs construct energy landscapes from data and navigate to the lowest-energy (most probable) states.

Key technical advantages:
- **Token-free**: No guessing game = cheaper and faster, critical for real-time systems (milliseconds/microseconds matter)
- **Internal verifiability**: You can inspect the model during training — it's not a black box
- **Double verification**: Internal (self-alignment via EBM architecture) + external (Lean4 proof languages)
- **Sparse data friendly**: Works well with incomplete datasets unlike LLMs
- **Constraint-compliant**: Can be formally forced to follow rules — crucial for cars, planes, power grids
- **Latent variables**: The model learns "rules about the data," not just patterns — stored as energy landscapes

On industry dynamics, Eve argues LLM investment faces **sunk cost lock-in**: billions poured into data centers, circular deals between LLM companies, hardware makers, and cloud providers create an ecosystem "impossible to break." Big tech companies do have internal EBM research (which she sees as validation), but percentage-wise, radical alternatives get far less funding than incremental LLM improvements.

Her strategic insight: **don't frame EBMs as LLM replacements**. Position them as compatible layers that handle what LLMs can't — spatial reasoning, data analysis, formal verification — while preserving all existing LLM investments. "We could actually try experiments to reduce the cost for your LLM portfolio companies."

For vibe coding specifically, Eve sees EBMs enabling a shift from "vibe coding in one specific language" to **coding in natural language with formally verified output** — where machine-verifiable proofs replace human code review, and the AI tells you "this part is not logically compatible" in natural language.

> "Intelligence which is language dependent... my thought processes don't really depend on any language. When you're driving a car, how much language do you actually use? Are you trying to predict the next word? Probably not. You just use your visual data, your state of your body, and you move."

### AI & I by Every — "为 LLM 无能为力之处构建的 AI 模型"

**嘉宾**：Eve，Logical Intelligence 创始人兼 CEO

**核心要点**：基于能量的模型（EBM）代表了与 LLM 根本不同的 AI 范式——无 Token、可自验证，特别适合正确性不容妥协的关键任务系统。

Logical Intelligence 正在构建**带潜变量的 EBM**（代号 Kona），专注于软件和硬件正确性。Eve 的核心论点：LLM 本质上是在玩 Token 猜谜游戏——自回归模型一次只能选一个方向，犯错后无法回头，且缺乏内部可验证性。她的类比：LLM 导航旧金山就像一个有隧道视野的人只能向前走，有时掉进看得见但避不开的坑里。

相比之下，EBM 就像拥有能量景观的**鸟瞰视角**——能同时看到所有可能状态，遇到障碍时选择不同路线。这来自物理学原理：正如物理系统通过最小化能量找到稳定态（像疲惫的人最终躺在沙发上），EBM 从数据构建能量景观并导航到最低能量（最可能）状态。

关键技术优势：
- **无 Token**：没有猜谜游戏 = 更便宜更快，实时系统关键
- **内部可验证**：训练过程中可检查模型——不是黑盒
- **双重验证**：内部（EBM 架构自对齐）+ 外部（Lean4 证明语言）
- **稀疏数据友好**：比 LLM 更适合不完整数据集
- **约束 compliant**：可被形式化强制遵循规则——对汽车、飞机、电网至关重要
- **潜变量**：模型学习"数据的规则"而非仅模式——以能量景观存储

在行业动态方面，Eve 认为 LLM 投资面临**沉没成本锁定**：数十亿投入数据中心，LLM 公司、硬件商、云提供商之间的循环交易创造了一个"不可能打破"的生态系统。大科技公司确实有内部 EBM 研究（她将其视为验证），但占比而言，激进替代方案获得的资金远少于增量式 LLM 改进。

她的战略洞察：**不要将 EBM 定位为 LLM 替代品**。而是定位为兼容层，处理 LLM 无法做到的事情——空间推理、数据分析、形式化验证，同时保留所有现有 LLM 投资。

> "依赖于语言的智能……我的思维过程实际上并不依赖任何语言。当你开车时，你实际使用了多少语言？你可能在预测下一个词吗？大概不会。"
