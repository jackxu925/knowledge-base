# Claude Code 产品负责人 Cat Wu：AI 时代 PM 该做的 3 件事

> Claude Code 产品负责人 Cat Wu 在 Lenny's Podcast 访谈的解读。核心观点：6 个月 roadmap 已死，PM 的角色从"决策源头"变成"让协作不需要 PM"，最值钱的是"既能想又能做"的工程师。

---

## TL;DR

Anthropic 的 PM 工作方式已经和传统 PM 完全不同。三件事：① 放弃长 roadmap，采用 Research Preview 模式；② PM 搭流水线让团队自运转，而不是亲自跑流程；③ 招有 product taste 的工程师，让"判断做什么"成为核心竞争力。

---

## 核心观点

### 一、6 个月的 roadmap 已经死了

**前提崩塌**：
- 写代码不再是瓶颈（AI coding）
- 模型能力每 3-6 个月跳一档

**案例**：Claude Code 早期做了 to-do list 功能帮助模型追踪修改，Opus 4 出来后模型自己能做了，该功能变成多余。

**Anthropic 的应对 — Research Preview**：
- 旧契约："说要发的必须发，发了必须 GA 质量"
- 新契约："这是实验，可能两周后改主意"
- 结果：工程师周末写完直接上，不用过 GTM；用户心甘情愿当反馈源

> 旧 PM 一半时间在管理"我们承诺了什么"，新 PM 一半时间在管理"怎么让承诺更模糊"

### 二、PM 是让别人不用开会的人

Cat Wu 现在的三件日常工作：

**1. 定团队原则，不写 PRD**
- 写很短的清单（核心用户、为什么是他们、什么场景开箱即用）
- 让团队任何人能自己拍板，不用回来问 PM
- 把"决策源头"拆掉

**2. 搭 Launch Room 流水线**
- 工程师贴功能 → 第二天文档/PMM/DevRel 自动接进 → 第三天发布
- PM 不在这条链路上跑，PM 在搭这条链路

**3. 每周整团队对一次指标**
- 不是为了 KPI，是为了让所有人对业务有同样深的理解
- 下次决策时任何人都能直接拍板

> 公司里一天跑五个会的 PM，在 Anthropic 语境里是低效的——他越忙，说明搭的基础设施越烂。

### 三、最值钱的是"既能想又能做"的工程师

**Anthropic 招人偏好**：有 product taste 的工程师

**角色重新定义**：

| 角色 | 旧定义 | 新定义 |
|------|--------|--------|
| 工程师 | 实现 PRD | 自己判断做什么 + 直接实现 |
| PM | 写 PRD + 协调资源 | 搭流水线 + 压缩"想法→用户"时间 |
| 设计师 | 独立设计环节 | 介入工程师早期，不做独立交付物 |

**PM 能力转型**：
- 流程型 PM：正在被淘汰
- 判断型 PM：杠杆被放大
- 释放出来的时间做：product taste、写 evals、看用户信号、判断模型能力边界

### 四、双核分工：按时间尺度切

**Cat & Boris 的分工**（不按职能，按时间）：

- **Boris（3-6 个月外）**：模型能力跳到哪一档、产品形态应该是什么
- **Cat（3 个月内）**：营销/销售/财务/容量/跨团队对齐全部捋顺

**为什么合理**：
- 远期需要技术远视和大判断，不需要操心落地
- 近期需要协同打通和细节耐心，不需要重新构想未来
- 两个尺度工作模式完全不同，一个人同时干两头都不到位
